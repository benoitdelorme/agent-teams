# Design system — agent-teams board

The index of what this system declares. Scope: `tools/board/index.html`, the kanban
served by `bin/teams-board` — the surface where a human dispatches and supervises three
Claude sessions.

## What this is

A **dispatch console**, not a project tracker. The columns are handoff points between a
human and autonomous agents; the log is a transcript of machine traffic; the header
pills are live process state. Every choice below descends from that reading.

**The system's one semantic rule:** colour encodes *who is speaking, and whether it
concerns you*. Cool hues are agents at work — periwinkle for assigned, mint for
finished; they are ambient and ask nothing. Warm hues mark a person: amber for what you
typed, coral for an agent that has stopped and needs you. Scanning a log means scanning
for warmth.

## Implementation

Tailwind v4, loaded in the browser from `@tailwindcss/browser@4.3.3` (pinned). Tokens
live in the `@theme` block of `tools/board/index.html`; components are `@apply`
compositions in `@layer components`.

Components are named classes rather than utility strings in the markup because most of
the markup is generated by JavaScript at runtime. Named classes keep every rule in the
compiled stylesheet, where it cannot depend on a class ever appearing in the DOM.

## Derived versus filled-in

The prior stylesheet was read before anything was written here.

**Derived — kept from the code as it stood:**
- the mono stack (`SF Mono` / `JetBrains Mono` / `ui-monospace`)
- the five-column set and their order
- a green for done and a glow on a working dot
- generated per-team badge hues, and `color-mix` for their ground
- the drag-ghost treatment: clone, 2.5° rotation, lifted shadow
- commit-on-blur, and never clobbering the field under the cursor

**Filled-in — proposed here, no prior value:**
- the cool violet-ink ground ramp and the paper/mute/faint ink ramp
- all four semantic hues, and the rule that assigns them
- the radius hierarchy (the prior file had two radii used interchangeably)
- Instrument Sans, and the type scale
- the full-page ticket screen (the prior ticket was an 860px dialog)

## Rejected, and why

**A warm brown-black ground under an orange accent.** Built first, at the human's
request, then withdrawn by them. The fault was structural, not a matter of taste:
accent and ground occupied the same hue family, so nothing separated a chip from the
card behind it, and the whole surface read muddy. The replacement puts a cool ground
under warm markers, which is also what let the semantic rule become sharper — warmth now
means *this concerns you*, which it could not mean when everything was warm.

## Deliberately removed

Three treatments in the prior file were generic tells, not decisions:
- `text-transform: uppercase` on column heads and field labels
- meta as a run joined by middle dots (`créé X · maj Y · par Z`)
- a single radius applied regardless of an element's weight

## Scope of this system

Everything here describes `tools/board/index.html` and nothing else. The contracts are
framework-agnostic on purpose: a role and its enumerated states, never framework code,
so the system survives a change of runtime.
